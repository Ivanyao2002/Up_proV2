**Comportement attendu**

- `search=ndja fabrice` → **1 seul item** (`Fabrice N'dja`) ou au minimum `pagination.total = 1`.
- Les autres chauffeurs (Kevine Boudalha, Seed, Kyc Test…) **ne doivent pas** apparaître.

**Comportement actuel**

- `pagination.total` reste **10** (liste complète).
- Le paramètre `search` est **ignoré côté serveur**.

**Demande backend**

Implémenter le filtre `search` sur `GET /v1/admin/kyc/queue` :

| Paramètre | Type | Description |
|-----------|------|-------------|
| `search` | `string` | Recherche insensible à la casse sur `displayName`, `firstName`, `lastName`, `phone`, `zoneName`, `partnerName` |
| `page` | `number` | Déjà utilisé par le front |
| `limit` | `number` | Déjà utilisé par le front |

**Critères d'acceptation**

| # | Critère |
|---|---------|
| 1 | `?search=ndja` ou `?search=fabrice` → retourne uniquement `Fabrice N'dja` |
| 2 | `pagination.total` reflète le nombre de lignes **après** filtre recherche |
| 3 | Recherche compatible avec `page` / `limit` (pagination sur le résultat filtré) |
| 4 | Documenter les query params dans Swagger (`/v1/admin/kyc/queue`) |
| 5 | Normaliser `submittedAt` en **ISO 8601** (`2026-06-12T09:17:32.000Z`) — format actuel `Fri Jun 12 2026…` fragile pour le front |

**Travail front (après livraison API)**

- Retirer le contournement de recherche côté client si ajouté.
- Conserver l'envoi de `search` via `buildV1ListQuery` (déjà en place).

**Ne pas faire**

- Charger toute la file côté front et filtrer en JavaScript en production (ne scale pas).

### KYC-QUEUE-DATE-01 — Filtre date ignoré sur la file KYC admin (priorité moyenne)

**Problème constaté**

Le front envoie `dateFrom` / `dateTo` (filtre sur **date de soumission** `submittedAt`) mais l'API **ne les applique pas** — même total et mêmes lignes qu'avec une plage vide ou absurde (ex. `dateFrom=2099-01-01`).

**Requête type**

```http
GET /v1/admin/kyc/queue?page=1&limit=25&dateFrom=2026-06-10&dateTo=2026-06-12
```

**Swagger actuel**

- `GET /v1/admin/kyc/queue` : **aucun paramètre** documenté (ni `page`, `limit`, `search`, ni dates).

**Demande backend**

| Paramètre | Type | Champ filtré |
|-----------|------|--------------|
| `dateFrom` | `YYYY-MM-DD` | `submittedAt >= début de journée` |
| `dateTo` | `YYYY-MM-DD` | `submittedAt <= fin de journée` |

**Critères d'acceptation**

| # | Critère |
|---|---------|
| 1 | Plage `2026-06-12` → `2026-06-12` ne retourne que les dossiers soumis ce jour-là |
| 2 | Compatible avec `search`, `page`, `limit` |
| 3 | Params documentés Swagger |

**Travail front (en attendant)**

- Contournement actuel : chargement multi-pages + filtre client sur `submitted_at` (voir `kyc.service.ts`).
- À retirer quand l'API filtre côté SQL.
