## Nouvelles demandes du jour (11/06/2026)

### DR-ORDERS-FILTER-01 — Filtre courses par chauffeur (priorité haute)

**Problème constaté**

- Fiche course `TR-5E355396` : chauffeur **Kouassi Yao** (`DEV-DRV-001`) bien affiché.
- Fiche chauffeur → onglet **Activité** : « Aucune course ».

**Cause**

Le front appelle `GET /v1/admin/orders` **sans filtre chauffeur**, puis filtre en JavaScript sur `driver_id`. Fragile (pagination + champ parfois absent en liste).

**Demande backend (recommandée)**

Étendre la route existante :

```http
GET /v1/admin/orders?driverId={uuid}&page=1&limit=25
```

**Alternative équivalente**

```http
GET /v1/admin/drivers/{driverId}/orders?page=1&limit=25
```

**Critères d'acceptation**

| # | Critère |
|---|---------|
| 1 | Filtre `driverId` (UUID chauffeur) côté SQL, pas côté client |
| 2 | `pagination.total` = nombre de courses du chauffeur |
| 3 | Chaque item liste contient `driver_id` renseigné (pas seulement `driver.displayName`) |
| 4 | Compatible avec filtres existants (`status`, `dateFrom`, `dateTo`, `service`) |
| 5 | Réponse : même shape que `GET /v1/admin/orders` (`rides`, `deliveries`, `pagination`) |

**Exemple attendu**

```http
GET /v1/admin/orders?driverId=abc-uuid-kouassi&page=1&limit=25
```

```json
{
  "status": "ok",
  "rides": [
    {
      "id": "5e355396-36b7-48fe-a7ef-9999f59e3f9d",
      "order_reference": "TR-5E355396",
      "driver_id": "abc-uuid-kouassi",
      "status": "completed",
      "pickup_address": "Grand-Bassam, …",
      "dropoff_address": "220 logements",
      "final_price_xof": 4500,
      "created_at": "2026-06-11T02:19:48+00:00"
    }
  ],
  "deliveries": [],
  "pagination": { "page": 1, "limit": 25, "total": 1, "totalPages": 1 }
}
```

**Travail front (après livraison API)**

- `ListParams` + `v1Pagination.ts` : param `driverId`
- `driverDetail.service.ts` : `fetchAdminOrdersList({ driver_id, page, per_page })` au lieu du filtre JS global
- Pagination serveur sur l'onglet Activité (`DriverDetailPage`)

**Ne pas faire**

- Embarquer toute la liste des courses dans `GET /v1/drivers/{id}` (ne scale pas, mélange les responsabilités).

## Exemples — ce qui n'a pas été fait (hier → aujourd'hui)

### 1. Activité chauffeur vide alors que la course existe

| Écran | URL / ref | Résultat |
|-------|-----------|----------|
| Course | `/admin/ops/trips/…` · **TR-5E355396** | Terminée, chauffeur Kouassi Yao |
| Chauffeur | `/admin/fleet/drivers/{uuid}` · **Kouassi Yao** | Activité : « Aucune course » |

**Pourquoi** : pas de route « courses du chauffeur » ; le front pioche dans `GET /v1/admin/orders` (page globale) et filtre `driver_id` — champ souvent absent ou hors page.

**Action** : **DR-ORDERS-FILTER-01** (backend) puis branchement front.

---

### 2. Page Zones — pas de pagination serveur ni filtres avancés

**Aujourd'hui** : `ZonesListPage` charge l'overview carte + tableau sans pagination API.

```tsx
// ZonesListPage.tsx — pagination désactivée
pagination={false}
```

**Attendu (ZN-LIST-01)** : comme la page Courses — `page` / `limit` vers `GET /v1/admin/zones`, filtres franchise et ville, tableau synchronisé avec la carte.

**Exemple** : 80 zones en base → tout est chargé ; impossible de filtrer « zones Partner Dev Abidjan » côté serveur.

---

### 3. Transactions — libellé franchise encore UUID (backend)

**Front fait** : filtres franchise / partenaire branchés (`FN-TRANS-01` partiel).

**Backend non fait** (`FN-TRANS-LABELS-01`) :

```json
// GET /v1/admin/finance/transactions
{
  "franchise": { "name": "a1b2c3d4-e5f6-7890-abcd-ef1234567890" }
}
```

**Impact UI** : colonne Franchise affiche l'UUID au lieu de « Abidjan Sud ».

---

### 4. `offer_outcome` — colonne UI sans données API

**UI prête** : `DriverDetailPage` a une colonne pour l'issue dispatch (accepté / refusé / expiré).

**Mapper non branché** : `mapOrdersToDriverTrips` ne lit pas `metadata.dispatch.offers` depuis l'API v1.

**Exemple** : en mock MSW, la course TR-… peut avoir `"offer_outcome": "declined"` ; en prod API, la colonne reste vide.
